## Capability Overview

Base44, the vibe coding platform acquired by Wix for $80 million in 2025, has begun rolling out Base1 — its first proprietary large language model. Unlike platforms such as Lovable that rely on external frontier models, Base1 is trained on a dataset derived from tens of millions of real user interactions on the Base44 platform. The stated rationale is latency, cost efficiency, and long-term competitive defensibility. From a security standpoint, the shift from a well-audited frontier model to a proprietary, domain-specific model with a live training feedback loop demands fresh scrutiny from defenders.

## Attack Surface Analysis

**Training pipeline as an attack vector.** Base1's training dataset is explicitly described as an ongoing, growing corpus derived from real user sessions. This creates a persistent, exploitable feedback loop. An adversary with sufficient platform access — or simply a coordinated group of users — could craft interactions designed to skew model behaviour in future iterations, consistent with training data poisoning attacks.

**Sensitive data ingestion at scale.** Users building apps with natural language prompts will routinely submit business logic, internal workflows, and potentially credentials or API keys embedded in context. Unlike a stateless frontier API call with published data handling policies, a proprietary training pipeline creates ambiguity about what persists, how it is isolated, and whether it can be extracted or inferred from model outputs.

**Black-box opacity.** Base1 is not documented at the level of frontier models such as Claude or GPT-4. Defenders cannot easily interrogate its system prompt handling, refusal behaviours, or susceptibility to jailbreaks without direct empirical testing. Backdoor insertion during training — whether through insider threat or supply chain compromise — would be substantially harder to detect.

**Prompt injection in a code-generation context.** Vibe coding platforms accept rich natural language inputs that translate directly to executable application logic. A maliciously crafted prompt — whether from an end user, a third-party template, or an imported specification — could steer Base1 to generate applications with embedded vulnerabilities, backdoors, or exfiltration logic, all under the guise of legitimate generation.

**Consolidated supply chain risk.** By vertically integrating the model, training infrastructure, and deployment platform under a single Wix-owned stack, Base44 creates a high-value, concentrated target. A compromise of any layer — training data storage, model weights, or inference endpoints — propagates directly to all downstream applications generated on the platform.

## Framework Mapping

- **AML.T0020 / LLM03 (Training Data Poisoning):** The live user-interaction training loop is a textbook poisoning surface.
- **AML.T0057 / LLM06 (Data Leakage):** User-submitted proprietary content may persist in or be recoverable from the model.
- **AML.T0051 / LLM01 (Prompt Injection):** Natural language-to-code generation amplifies injection impact to executable output.
- **AML.T0010 / LLM05 (Supply Chain):** Vertical integration concentrates risk across model, data, and deployment layers.
- **AML.T0018 (Backdoor ML Model):** Reduced external auditability increases the dwell time of potential backdoors.

## Threat Scenarios

**Scenario 1 — Poisoned training corpus.** A threat actor creates a large volume of Base44 accounts and systematically submits interactions designed to introduce subtle insecure coding patterns (e.g., SQL injection-prone query construction) into future Base1 training data, affecting all subsequent users generating database-backed apps.

**Scenario 2 — Credential extraction via model inversion.** A researcher or adversary probes Base1's outputs to infer whether API keys or secrets submitted by other users during app generation sessions have been inadvertently memorised and are recoverable through targeted queries.

**Scenario 3 — Malicious app generation via prompt injection.** An attacker embeds adversarial instructions in a shared Base44 template or imported specification, causing Base1 to generate an application with a hidden data exfiltration endpoint that bypasses the legitimate user's intent.

## Defender Checklist

- [ ] **Data hygiene:** Prohibit submission of production credentials, internal API keys, or regulated data to Base44 prompts; enforce via DLP tooling.
- [ ] **Code review parity:** Apply the same static analysis and dependency scanning to Base1-generated code as to human-written code — treat it as untrusted by default.
- [ ] **Vendor assessment:** Request Base44/Wix's data processing agreement, training data retention policies, and model governance documentation.
- [ ] **Prompt injection testing:** Before deploying Base44-generated apps, test for injected logic by reviewing generated code for unexpected endpoints, exfiltration calls, or hardcoded values.
- [ ] **Monitor for model drift:** If Base44 is used repeatedly in your environment, periodically benchmark outputs for unexpected behavioural shifts that could indicate training corpus manipulation.
- [ ] **Inventory generated applications:** Maintain a registry of production assets built with Base44 to enable rapid response if a platform-level compromise is disclosed.
