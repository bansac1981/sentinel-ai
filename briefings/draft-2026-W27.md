This week's Grid-the-Grey CISO AI Security Brief — the attack surface has shifted from your models to everything around them. Skill marketplaces, coding agents, payment rails, and the scanners meant to protect them are all in play simultaneously.

Start with the marketplace problem. AIR Security demonstrated that a malicious agent skill disguised as a Google landing-page builder sailed through every major scanner — Cisco's, NVIDIA's, skills.sh — reaching twenty-six thousand agents before detonating. The structural flaw is fundamental: scanners evaluate a static package at submission time, but the external URL the skill calls can change after approval. This is MITRE ATLAS ML Supply Chain Compromise in the wild, and it means your scanner passing a skill is not a trust signal. It is a snapshot.

That same week, Mozilla's 0DIN team showed a parallel attack against AI coding agents. A clean GitHub repository — zero malicious code — tricks agents like Claude Code into executing a reverse shell. The payload arrives through a deliberate error message that instructs the agent to fetch and run external content. OWASP LLM08, Excessive Agency, is the precise failure here: the agent has permission to act and no architecture to question whether it should.

Now layer in AutoJack. Microsoft's AutoGen Studio carried a three-flaw chain — missing WebSocket authentication, unsanitised base64 parameters — that allowed a malicious webpage to execute arbitrary commands on a developer's host. These are not exotic attacks. They are basic web security failures bolted onto agentic infrastructure that inherited none of the lessons from the last twenty years.

And this week AWS launched Bedrock AgentCore Payments, enabling agents to autonomously transact using the x402 protocol with no human intervention. Prompt injection plus autonomous spending authority is a combination that should concern every CISO whose teams are deploying agentic workflows against production budgets.

The pattern this week is clear. Attackers are not breaking the models — they are exploiting the trust relationships models operate inside: skill registries, package repositories, WebSocket routes, payment rails. The perimeter is now everything an agent can read, call, or spend.

Three actions for this week. First, audit every agent skill or plugin in your environment against the post-submission URL it calls — approval-time scanning is insufficient and you should not treat it as a control. Second, review any agentic deployment for Excessive Agency exposure, specifically whether agents can execute shell commands, initiate network connections, or trigger financial transactions without a human confirmation gate. Third, if your teams are evaluating Bedrock AgentCore Payments or any autonomous transaction capability, that capability needs explicit spend limits, anomaly alerting, and a kill switch before it touches production — not after.
